## 一次被真机抓到的缺陷（已修，N6 钉住）

第一版没有跨通道去重。`fresh_channel_of` 是「先看 want+标记、再看 typeid」，
所以**同一条行可以同时够两个通道**：助眠词搜到的「助眠」朗读稿落在 228，
按 want+标记 是 asmr；长词搜到同一 bvid 落在 228，按 typeid 是 long。三个通道
各有各的 `seen`，于是同一条视频被上架两次、两个标签。

真机截图直接看到了它：`ASMR · 39:52` 与 `人文历史 · 39:52` 是同一个视频
（`final_shelf_p2.png`，修复前）。

修法是让三个通道共享一个 `claimed` bvid 集合，按 asmr → long → short 的顺序
构建，高权重通道先认领。修复后的活体读数 16 格 **bvid 零重复**
（`R1_live_channels.log`）。这个缺陷在 fixture 里查不出来 —— 我按通道统计
fixture 的重复 bvid 是 **0**，因为 fixture 的十页里没有这条跨界行；它只在
真实回包上出现。所以这一节的证据是截图与活体探针，不是契约测试。

## 一次被真机读数推翻的设计（已改）

第一版只在「线上分区是 `21 日常`」时把标签改写成 `ASMR`，理由是不想覆盖真实分区名。
真机第一次读出来是这样：

```
slot01 音乐综合 · 1.0h  【Playlist】…白噪音      <- ASMR 通道
slot08 音乐综合 · 2:08  【纯音乐分享】银莲花…    <- short 通道
slot16 音乐综合 · 14:47 月の守護者の歌…         <- short 通道
```

**同一个标签出现在两个通道上**，用户没法从界面上看出「ASMR 拿了一半」这件事
就是生效了。卡片第二行是宿主留给插件的唯一通道信号（D5/D6），所以规则改成：
**ASMR 通道的行一律写 `ASMR`**，长/短通道保留真实分区名（那里分区名才是有用信息）。
改完的读数见上表 —— 8/8 个 ASMR 槽都是 `ASMR · …`，6 个长格与 2 个短格保留原分区。

这条是 `T16#07` 与 `T16#03` 两条断言钉住的，N1 负向控制会连带打到它。

## 跑批污染（工具层，不是产品缺陷）

`flutter test` 在负载下偶尔整段 `did not complete`（宿主 VM 超时，后续用例
全被标成未完成）。它会**掩盖**真正的目标用例 —— N5 第一次就是这么报的
（T11/T13 红、`T16#08` 反而没红）。`negative_controls.mjs` 现在把「≥3 个未完成」
判为污染并整批重跑（最多三次），每次记录 `尝试=N`。本轮 N3/N4 各重跑过一次，
其余一次通过。

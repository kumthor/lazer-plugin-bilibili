# v0.6.0 — 词表换血：ASMR 占一半，`208` 出局

用户 2026-11-24 的决定：去掉 `校园学习(208)`、减少 `公开课`/`讲座`、加入 `ASMR`/`助眠`/`白噪音` 并给到一半槽位。

## 词表（10 词 × `ps=30`，三通道）

| 通道 | 词 | 白名单 |
| :--- | :--- | :--- |
| asmr | `ASMR` `助眠` `白噪音` | `21 日常` **且** 标题/标签带 asmr/助眠/白噪音 等标记；或白名单内但自报 ASMR |
| long | `有声书` `文学朗读` `听书` `讲座` | 195 / 228 / 124 / 201 / 207（**208 已移除**） |
| short | `鬼畜` `歌切` `纯音乐` | 31 / 130 / 59 / 29 / 193 / 30 / 26 / 22 / 216 / 126 |

槽位模式 `asmr,asmr,long,asmr,long,asmr,long,short` ×2 = **8 asmr + 6 long + 2 short**。`公开课` 整词删除（它是 208 的主力，23/30 行落在校园学习），`讲座` 保留但只占长通道的四分之一。

`page_size` 从 20 提到 **30**：十词 `ps=30` 解码 465,598 B，加 `popular` 33,182 B 后 498,780 B，是换源前（206,027 B）的 2.42×、v0.5.0 出货版（313,859 B）的 1.59×。这是实测结论不是保守选择——它在**真站行**下仍然回答 16 格（`T16#05` 用 300 行原始字节跑）。这条门红了就说明 T9/R25 的墙回来了：处理办法是减词或退回 `ps=20`，不是调预算。

## 为什么 ASMR 靠标记而不是分区

四词 120 行 → **71 行落在 `21 日常`**，而那 71 行 100% 带 `asmr`/`助眠`/`白噪音` 等标记；对照词「分享课」的 21 行 **0/4** 带标记。所以规则是「21 + 标记」，不是「21」：

- 长/短词搜到的 21 行一律不收（词本身不是 ASMR 词）；
- ASMR 词搜到的 21 行也要有标记才收。

标记命中但分区不在白名单与 21 之内的行一律拒收——自报 ASMR 的网游视频不能靠标题上架。

## 一次被真机抓到的缺陷：跨通道重复

第一版没有跨通道去重。`fresh_channel_of` 是「先看 want+标记、再看 typeid」，所以**同一条行可以同时够两个通道**：助眠词搜到的「助眠」朗读稿落在 228，按 want+标记 是 asmr；长词搜到同一 bvid 落在 228，按 typeid 是 long。三个通道各有各的 `seen`，于是同一条视频被上架两次、两个标签。

真机截图直接看到了它：`ASMR · 39:52` 与 `人文历史 · 39:52` 是同一个视频。

修法是让三个通道共享一个 `claimed` bvid 集合，按 `asmr → long → short` 的顺序构建，高权重通道先认领。修复后活体读数 16 格 **bvid 零重复**。

这个缺陷在 fixture 里查不出来——按通道统计 fixture 的重复 bvid 是 0，因为 fixture 的十页里没有这条跨界行；它只在真实回包上出现。所以这一节的证据是截图与活体探针，不是契约测试。`T16#15` 是这条的回归钉。

## 一次被真机读数推翻的设计：卡片标签

第一版只在「线上分区是 `21 日常`」时把标签改写成 `ASMR`，理由是不想覆盖真实分区名。真机第一次读出来是这样：

```
slot01 音乐综合 · 1.0h   ← ASMR 通道
slot08 音乐综合 · 2:08   ← short 通道
slot16 音乐综合 · 14:47  ← short 通道
```

**同一个标签出现在两个通道上**，用户没法从界面看出「ASMR 拿了一半」这件事就是生效了。卡片第二行是宿主留给插件的唯一通道信号，所以规则改成：ASMR 通道的行一律写 `ASMR`，长/短通道保留真实分区名（那里分区名才是有用信息）。

## 验证

- 契约测试 **173 条**（v0.5.0 的 156 条里改写 17 条 → 新增 17 条 T16）。
- 负向控制 **N1–N6 全部按预期变红**，还原后 byte-identical：
  - N1 去掉「21 必须带标记」→ `T16#06`
  - N2 `208` 加回长白名单 → `T16#04`
  - N3 槽位改回 12 长 / 4 短 → `T16#01`（连带 `#03`）
  - N4 热度退化成单 `play` → `T16#09`
  - N5 降级顺序改 `asmr→short→long` → `T16#08`
  - N6 跨通道去重退回每通道各一份 → `T16#15`
- 打包 15/15 逐字节一致，安装 15/15 md5 一致。
- 真机：活体探针 16 格 = **8 ASMR + 6 人文历史 + 1 音乐综合 + 1 翻唱**，槽位逐格对上，bvid 零重复。

**N1 第一次是烂的**：原 `T16#06` 只用「长词的 21 行」（被 `want=="asmr"` 这一层拦下）与「ASMR 词的 21 行带标记」（被收），两者都不需要标记门就会按预期表现，所以去掉标记门时全绿。补了「ASMR 词 + tid 21 + 标题无标记」这一条之后 N1 才真正变红。这个缺口是负向控制抓出来的，不是事后推理。

## 工具层的一处坑

`flutter test` 在负载下偶尔整段 `did not complete`（宿主 VM 超时，后续用例全被标成未完成）。它会**掩盖**真正的目标用例——N5 第一次就是这么报的（T11/T13 红、`T16#08` 反而没红）。负向控制脚本现在把「≥3 个未完成」判为污染并整批重跑（最多三次）。

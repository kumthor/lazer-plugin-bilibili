# v0.4.4 — 首页音乐架只收音乐区

首页的音乐架以前混进了游戏、影视、鬼畜类视频：候选集只按「是不是多 P」筛，不看分区；而单 P 投稿被整条排掉，导致真正的音乐投稿反而上不了架。

## 改动

### 1. 候选集限定音乐区

两层候选，都要求 `pid_v2 == 1003`：

| 层 | 来源 | 顺序 |
|---|---|---|
| popular | `/x/web-interface/popular` 的音乐区行 | 保持 popular 原序 |
| chart | `/x/web-interface/ranking/v2?rid=3` 的音乐区行 | 保持榜单原序 |

`pid_v2` 是判据，不是 `tid`：同一个 `tid` 会跨两个分区出现（`tid=253` 动漫杂谈一次算二次元、一次算音乐，见 `evidence/t12/R2_popular_tname.log`）。`pid_v2 = 0` 是**真实取值**而不是缺字段（`evidence/t12/R5_popular_pid.log` 里 2/20 行如此），所以判据写成 `== 1003` 而不是「字段存在」。

### 2. `rid=3` 也要筛

音乐区榜单不是纯音乐区：实测 86/97 行 `pid_v2 = 1003`，其余是娱乐 1、二次元 2、鬼畜 3、游戏 1、知识 1、科技数码 1、动物 1、其他 1（`evidence/t12/R7_music_ranking_zones.log`）。不过滤就会把一个鬼畜视频摆到音乐架上。全站榜 `CHART_RID = "0"` 一行未动，`charts()` 与 `playlistSongs("chart:0")` 的返回完全不变。

### 3. 单 P 也是专辑

门槛从 `videos > 1` 改成 `videos >= 1`。单 P 行直接用 feed 自身携带的 `videos=1` / `pic` / `title` 上架，**不发 `view`**；`songCount = 1` 是真实值——`albumSongs` 对一条单 P 视频确实返回 1 行（`M.album_songs` 读 `view.pages`）。

`ALBUM_LIMIT = 16` 现在只对多 P 候选计数。否则 97 行榜单会被 16 条上限截断，而截掉的都是不需要请求的行。

## 没有按 `score` 排序

任务书原写「按 `score` 降序」。实测两件事推翻了它：

```
rid=3 rows=97   scoreMissing=0  score 取值集合={0}  scoreAscViolations=0
rid=0 rows=100  scoreMissing=0  score 取值集合={0}  scoreAscViolations=0
```

字段在、类型是 number、值全是 0，排序是语义上的空操作。而代价不是 0：

```
榜单 2 行   （T10#01 fixture）：  不排序 140/140 绿    排序 绿
榜单 100 行 （T10#10 fixture）：  不排序 140/140 绿    排序 408
```

`table.sort` 加闭包比较器在 97~100 行上把 `homeFeed` 推过 250k 指令预算。排序既无收益又会炸，所以保留榜单自身的返回顺序（`evidence/t12/T01_sort_budget.log`）。

| 项 | 结果 |
|---|---|

| 双宿主 | 2.0.300 **140/140**；2.1.0 **140/140** |

| 负向控制 B（门槛回 `videos > 1`） | `T6#15`/`T10#04`/`T10#04b` 变红，其余绿 |

新增的三条断言：

- `T10#01b` — 非音乐区 popular 行（`pid_v2=1008`）与 `pid_v2=0` 行都进不了架；
- `T10#01c` — 音乐区多 P 收、非音乐区多 P 拒（旧代码两个都收）；
- `T10#04b` — popular 音乐区 0 行时架子仍成形（`R5` 的真机形态）。这条是任务书要求「不能用真机现状当样本，否则断言恒真」的那一条。

## 已知取舍

- **真机 GUI 的架长没有数过**：证据是离线契约（两棵树各 140/140）加只读采样，没有在 2.1.0 成品 GUI 里数首页音乐架显示几条。
- **popular 音乐区 0/20 是一次采样**：它证明「0 是正常情况、架子必须能单独成形」，不证明「长期为 0」。实现按前者写，两种情况下都正确。
- **`rid=3` 那 11 行非音乐行的稳定性未验证**：实现按「必须过滤」写；若将来 `rid=3` 变成纯音乐区，这道过滤就是空操作，不会错。

# 🧪 哔哩哔哩插件黑盒测试指引

按真实使用动线（安装启用 → 登录 → 搜索 → 播放 → 歌词 → 收藏 → UP 主页 → 评论）整理的端到端验收清单。每条都给出宿主契约与预期表现，可照表逐项打勾。

> 前置：Lazer v2.0.210 及以上，插件已导入并启用，且已授予网络权限。

---

## 一、安装与启用

| 测试项 | 操作路径 | 宿主契约 | 预期结果 |
| :--- | :--- | :--- | :--- |

## 二、登录与会话

| 测试项 | 操作路径 | 宿主契约 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 扫码生成 | 登录框点扫码 | `qrKey` / `qrUrl` | 渲染出可被 B 站 App 识别的二维码（**不是** `{hint:` 开头的字符串） |
| 扫码确认 | 用 B 站 App 扫码并在手机确认 | `qrCheck` | 返回 `803`，登录态自动保存，左下角显示账号昵称与头像 |
| 旧码失效 | 打开登录页停留数分钟后再扫 | `qrCheck` | 提示二维码失效；重新打开登录页生成新码即可，不需要重装插件 |
| Cookie 登录 | 粘贴含 `SESSDATA` + `bili_jct` 的完整 Cookie | `loginCookie` | 登录成功并显示账号信息；缺字段时报错而非假装成功 |
| 会话恢复 | 重启 Lazer | `session` | 自动恢复登录态，无需重新扫码 |
| 退出登录 | 账号菜单退出 | `logout` | 回到未登录态；依赖登录态的页面提示登录而非报错崩溃 |

## 十、专辑名与分 P 入口（v0.4.5 / v0.4.6）

| 测试项 | 操作路径 | 宿主契约 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 列表行后缀 | 首页 / 榜单 / 相关推荐里的多 P 视频 | `homeFeed.featuredSongs` | 专辑名是 `标题 · N P`，**整串 ≤ 32 列**，后缀不被省略号吃掉；单 P 行是纯标题、无后缀 |
| 播放页升级 | 搜索一条多 P 视频 → 点播放 | `song` | 正在播放页的专辑行显示 `标题 · N P`（搜索页那一列留空，播完才出现） |
| 专辑页一致 | 从播放页点专辑行 → 专辑页 | `albumSongs` | 每个 P 的专辑名与列表页**逐字相同**；N 是这支视频的总 P 数，不随坏 P 缩小；标题是 `P1/P2 …`，与专辑名不同 |
| 收藏夹 | 打开默认收藏夹 | `favorites` | 曲目可播；宽屏列表的专辑列留空属预期（该接口不给 P 数） |
| 缓存 | 升级插件后首次打开 | 任意 | 旧的泛名 `B站视频` 可能残留 1 小时（宿主 `Track` 无 schema 版本）；清缓存后消失 |

**已知限制（非缺陷）**：多 P 视频的列表行 `duration` 是整个合集的时长，点那一行只播 P1——进度条按合集长度走。这是宿主把列表当队列的结果，插件侧零请求修不了。

## 十一、异常与边界

| 测试项 | 操作路径 | 宿主契约 | 预期结果 |
| :--- | :--- | :--- | :--- |
| 风控 | 短时间高频操作 | 任意 op | 返回 `429` 提示稍后重试；插件不自动重试、不崩溃 |
| 断网 | 断网后操作 | 任意 op | 显示网络错误；恢复网络后无需重启即可继续用 |
| 长时间挂机 | 连续播放数小时 | `stream` / `lyrics` | 无内存暴涨、无 VM 重启、歌词不漂移 |
| 未知操作 | 宿主调用插件未实现的 op | `call` | 返回结构化错误，插件不崩、不影响已加载的列表 |

## 判定标准

- **必修**：任何一项出现崩溃、白屏、登录掉线、列表整页报错。
- **可记录**：文案别扭（如宿主统一 401 文案为「请检查用户名和密码」）、加载慢于 6 秒（宿主缓存后会改善）。
- **非缺陷**：专辑 / 歌单 tab 为空、匿名态歌词不可用、UP 主页专辑区为空——均为上游数据层或宿主 UI 的固有限制，已在 README「已知限制」中说明。
